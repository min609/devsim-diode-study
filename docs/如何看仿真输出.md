# 如何看 DEVSIM 的仿真输出

> 这份文档解决一个问题：**屏幕上刷了几百行数字，哪些要看、怎么看、怎么判断结果可不可信。**

---

## 一、输出的三段结构

DEVSIM 跑一次仿真的输出，永远是这三段：

```
【第一段】启动信息      —— 数学库加载，正常现象，不用管
【第二段】建网格 + 求解 —— 信息量最大的一段
【第三段】你自己的打印   —— 你脚本里 print() 出来的结果
```

---

## 二、第一段：启动信息（正常，不用管）

```
Searching DEVSIM_MATH_LIBS="D:\devsim\.venv\Library\bin\mkl_rt.3.dll"
Loading "D:\devsim\.venv\Library\bin\mkl_rt.3.dll": Intel MKL with PARDISO LOADED
```

**含义**：DEVSIM 正在加载数学求解库。
- `PARDISO` = 稀疏矩阵直接求解器（半导体仿真用的高性能解法器）
- **看到这行 = 环境正常**。如果这里报 `MISSING DLL`，就是数学库没配好

---

## 三、第二段之一：建网格的回显

```
mid
bot
 (region: MyRegion)
 (contact: top)
 (contact: bot)
number of equations 465
```

| 行 | 含义 |
|---|---|
| `mid` / `bot` | 网格里的**标记点**（tag）——我们定义了 top / mid / bot 三个位置 |
| `(region: MyRegion)` | 定义了一个求解区域，名叫 MyRegion |
| `(contact: top)` / `(contact: bot)` | 定义了两个电极 |
| `number of equations 465` | **未知量个数 = 网格节点数**（只解泊松方程时，每个节点 1 个未知量） |

**接着变成 1395**：

```
number of equations 1395
```

**465 × 3 = 1395** —— 因为加入了漂移扩散后，每个节点有 **3 个未知量**：

```
电势 Potential  +  电子浓度 Electrons  +  空穴浓度 Holes
```

> 📌 **这是第一个该养成的直觉**：方程数 = 节点数 × 每个节点的未知量数。
> 想知道器件被离散成多细，看这个数就知道。

---

## 四、第二段之二：牛顿迭代日志（核心）

每一次偏压调整，DEVSIM 都要解一次**非线性方程组**，方法是**牛顿迭代**：

```
Iteration: 0
  Device: "MyDevice"    RelError: 1.00000e+00   AbsError: 8.88882e-02
    Region: "MyRegion"  RelError: 1.00000e+00   AbsError: 8.88882e-02
      Equation: "PotentialEquation"  RelError: 1.00000e+00   AbsError: 8.88882e-02
Iteration: 1
  Device: "MyDevice"    RelError: 4.91285e-01   AbsError: 8.58427e-02
...
Iteration: 11
  Device: "MyDevice"    RelError: 9.66324e-11   AbsError: 7.81762e-12   ← 收敛了
```

### 逐项含义

| 字段 | 含义 |
|---|---|
| `Iteration: N` | 第 N 次牛顿迭代 |
| `RelError` | **相对误差**——本次更新的量级相对于解本身的量级 |
| `AbsError` | 绝对误差 |
| 三级缩进 | Device（整个器件）→ Region（区域）→ Equation（每个方程） |

### 怎么判断"收敛了"

收敛判据是**我们自己设的**（在脚本里）：

```python
devsim.solve(type="dc", absolute_error=1e10, relative_error=1e-10, ...)
```

含义：**当 RelError < 1e-10 就算收敛**。

`absolute_error=1e10` 设得极大，等于"主要看相对误差"——这是 DEVSIM 官方示例的写法。

### ⚠️ 两个"别被吓到"的正常现象

1. **Iteration 0 的 RelError 常常是 1.0 或很大** —— 因为初始猜测很粗糙，正常
2. **中间的 RelError 会反弹**（比如从 0.19 跳到 2.2）—— 牛顿法**不是单调下降**的，只要最终降到判据以下就行

**真正的危险信号**：迭代到你设的上限（`maximum_iterations=30`）而 RelError 还停在 1e-3 以上 → 没收敛，结果不能用。

## 五、第三段：你自己的打印

```
  [OK ] V=+0.400 V   I_top=+4.487529e-04   I_bot=-4.488207e-04
```

- `[OK ]` = 这个偏压点收敛了；`[FAIL]` = 没收敛（电流记成 NaN）
- **两端电流应该大小相等、符号相反**（一个是流入、一个是流出）

---

## 六、⭐ 判断结果可不可信：三个检查

### 检查 1：收敛检查
看 `RelError` 是否降到 1e-10 以下。

### 检查 2：守恒检查（最重要，也最容易被忽略）

**基尔霍夫电流定律（KCL）**：电流从 top 流入、从 bot 流出，**两端电流之和必须为 0**。

```
|I_top + I_bot| / max(|I_top|, |I_bot|)    ← 相对不平衡度，应该接近 0%
```

**这个检查能抓出"收敛了但结果不可信"的情况**——这是仿真里最常见的陷阱。

### 检查 3：量级检查
- 正向电流应该随偏压**指数上升**
- 反向电流应该**饱和**（不随偏压显著变化）
- 电流不能出现负值（在正偏区）

---

## 七、你这次运行的实际结果：发现了一个真问题

把 39 个偏压点的 KCL 检查算出来：

| 偏压区间 | 两端电流不守恒程度 | 结论 |
|---|---|---|
| **+0.18 V ~ +0.60 V** | **0.00% ~ 3%** | ✅ 结果可信 |
| +0.10 V ~ +0.16 V | 2% ~ 18% | ⚠️ 勉强 |
| **-0.40 V ~ +0.08 V** | **最高 151%** | ❌ **不可信** |

具体例子：

| V | I_top | I_bot | 不平衡度 |
|---|---|---|---|
| +0.60 V | +7.9853e-01 | -7.9853e-01 | **0.00%** ✅ |
| +0.20 V | +1.1363e-06 | -1.0993e-06 | 3.26% ✅ |
| -0.15 V | -5.1108e-08 | -2.6484e-08 | **151.8%** ❌ |
| -0.30 V | -5.8702e-08 | +6.3868e-09 | **89.1%** ❌ |

### 为什么会这样？（这是关键理解）

**不是程序错了，是数值精度的物理限制**：

1. **反偏时电流极小**（~1e-8 A/cm²），而器件内部的载流子密度和通量是 O(1) 量级
2. 电流 = 载流子通量的**差值**——大数相减，**灾难性抵消**（catastrophic cancellation）
3. 于是电流**丢掉了约 8 位有效数字**，剩下的就是数值噪声
4. 我们设的 `relative_error=1e-10` 是作用在**解变量**（电势、载流子浓度）上的，**不是作用在电流上**——所以"解收敛了"不等于"电流算准了"

### 这个发现的意义（复试时能讲的东西）

> "我做了电流守恒自检，发现正偏区守恒到 0.01%，但反偏区高达 150%。
> 分析后确认这是**低电流下的灾难性抵消**导致的精度损失，不是收敛失败——
> 因此**反偏区间的绝对电流值不可用于定量分析，只能看趋势**。"

**这段话的分量，远大于"我跑通了一个二极管仿真"。** 它说明你知道**仿真的结果需要验证**。

## 八、可复用的检查清单

以后跑任何仿真，按这个顺序看：

- [ ] **数学库加载正常？**（第一段没有 MISSING DLL）
- [ ] **方程数量对不对？**（= 节点数 × 未知量数）
- [ ] **每个偏压点都收敛？**（`[OK]` 的比例，RelError 是否降到判据以下）
- [ ] **守恒量检查通过？**（这里：I_top + I_bot ≈ 0）
- [ ] **趋势符合物理？**（正偏指数上升、反偏饱和）
- [ ] **异常区间标注出来**，不要当成有效数据用

---

## 九、下一步可以做的实验

1. **收紧收敛容差**：把 `relative_error` 从 `1e-10` 改成 `1e-13`，看反偏区守恒是否改善
2. **改用电流守恒作为收敛判据**：DEVSIM 的 `solve()` 支持更细的收敛控制
3. **加密网格**：看是否是离散误差导致
4. **只在可信区间做定量分析**：把 -0.4V ~ 0.1V 的数据单独标注

> 实验 1 是最快能验证的，也是最值得先做的。
